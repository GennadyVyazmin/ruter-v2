# Ruter v2 — Debian / Ubuntu test gateway

Отдельная экспериментальная версия Ruter для Debian и Ubuntu x86-64 с systemd. Использует
`sing-box-lx 1.14.3-lx.20`, VLESS + REALITY, Vision по TCP, XHTTP `stream-up`
и UDP через XUDP. MetaCubeXD позволяет выбирать серверы через веб-интерфейс.
Исходники не содержат подписку или клиентские ключи.

**Не устанавливать на production-шлюз.** Перед запуском установщик требует
подтвердить найденные сетевые настройки ответом «да» и откажется работать при активном `sing-box.service`
или временном тестовом шлюзе. Проект не меняет существующий `sing-box.service`
или системный маршрут по умолчанию.

## Установка на отдельной Debian / Ubuntu

1. Убедитесь, что машина использует обычный локальный шлюз, а не тестовый VPN.
2. Если на ней запущен прежний временный XHTTP-шлюз, остановите его штатным
   скриптом. Установщик сам проверит, что тот уже не активен.
3. На машине с `wget` выполните одну строку из домашней папки:

   ```bash
   wget -qO "$HOME/ruter-install.sh" https://raw.githubusercontent.com/GennadyVyazmin/ruter-v2/main/bootstrap.sh && sudo bash "$HOME/ruter-install.sh"
   ```

   Загрузчик сначала ставит `sudo`, `git`, `curl`, сертификаты, Python и сетевые
   утилиты. Затем определяет пользователя и LAN-интерфейс, скачивает исходники
   и запускает основную установку. После прерванной установки ту же команду
   можно повторить: существующий чистый репозиторий обновится без перезаписи
   локальных изменений. Если LAN-интерфейсов несколько, попросит
   выбрать. На системе без `sudo` сначала войдите через `su`, затем выполните
   ту же строку без слова `sudo`. Если нет даже `wget`, сначала установите
   `wget` через `apt` от root либо скопируйте `bootstrap.sh` через `scp`.
   Загрузчик лежит в домашней папке, исходники — в `~/ruter-v2`, программа —
   в `/opt/ruter-v2`, настройки — в `/etc/ruter-v2`, данные — в `/var/lib/ruter-v2`.
   Постоянных файлов Ruter в `/tmp` нет.
4. Вставьте HTTPS-ссылку подписки или одиночную VLESS-ссылку по запросу.
   Подписка сохраняется в `/etc/ruter-v2/source.txt` с доступом только root.
5. Установка проверит конфиг ядром и оставит службы **остановленными**.
   Введите `ruter` для главного меню и выберите пункт 4 для запуска шлюза.
6. Автозапуск при перезагрузке включён по умолчанию. Пункт 8 позволяет выключить
   или включить его; установка не запускает шлюз немедленно.

Команда `ruter` сама запросит права администратора и откроет меню. Первым
всегда идёт установка, вторым —
обновление подписки из текущего источника, третьим — вставка новой ссылки.
Удаление — последний пункт.

Пункт **9 — обновление самого Ruter v2 из GitHub**, пункт 10 — удаление.
Обновление программы сохраняет конфиг и подписку, не перезапускает ядро и
не прерывает работающий шлюз. Старый Ruter v2 без этого пункта обновляется
той же командой bootstrap выше: он обнаруживает установленную программу.
Пользовательский выбор автозапуска при обновлении сохраняется.
Подробности миграции, отката и проверок: [ROUTING-LIFECYCLE.md](ROUTING-LIFECYCLE.md).

## Подключение тестовых клиентов

Только на нужном тестовом устройстве установите IPv4-шлюз, равный адресу
машины с Ruter v2, и DNS `1.1.1.1` или `8.8.8.8`. DHCP всей сети менять
не нужно.
После запуска локальный SOCKS/mixed доступен на `127.0.0.1:2080`, LAN mixed —
на `<LAN-IP>:2081`. Порты совпадают с прежней конфигурацией Ruter v1:
при сохранении IP шлюза адрес прокси в контейнерах менять не нужно.
Перед установкой старый шлюз необходимо остановить и освободить эти порты.
Обновление исходников само по себе не меняет уже запущенный конфиг v2:
новые порты применяются при установке или следующем обновлении подписки.

MetaCubeXD: `http://<LAN-IP>:9190/ui/`. Секретный ключ не требуется:
поле Secret в MetaCubeXD оставьте пустым. API слушает LAN-IP, а не все
адреса. Это привязка интерфейса, не ограничение источников: любой, у кого
есть сетевой доступ к порту 9190 (включая маршрутизируемые сети/VPN),
может управлять шлюзом. Не публикуйте этот порт в интернет и ограничьте
доступ доверенной сетью на межсетевом экране.
Новая установка не создаёт файл ключа. Для существующей установки нужно
обновить установленный код и затем обновить подписку: только это пересоздаст
конфигурацию без секрета. Простое скачивание исходников старый конфиг не меняет.

## Что умеет

- Импорт обычного текста и Base64-подписки с VLESS-ссылками.
- REALITY + TCP/Vision и REALITY + XHTTP (`stream-up`, `packet-up`,
  `stream-one`, `auto`), а также прежние WS/gRPC/HTTPUpgrade;
  XUDP для UDP во всех поддерживаемых профилях.
- Сохранение ссылки подписки; пункт 2 повторно скачивает её без ручного ввода.
- Автоматический выбор по задержке (`urltest`) и ручной выбор в MetaCubeXD.
- Раздельные файлы и службы `ruter-v2-*`, отдельная таблица маршрутов 220.
- Проверка конфига до активации; при ошибке обновления возвращается прежний.
- Диагностика через `journalctl` в меню.

Пока **не поддерживаются** JSON-подписки, VLESS Encryption,
XHTTP вместе с Vision flow, автоматический DNS для клиентов
и настройка GeoSite/GeoIP. Несовместимые ссылки пропускаются с предупреждением.
Параметр `pqv` в VLESS-ссылке не обрабатывается: поддержка ML-DSA требует
отдельного теста. Нельзя считать успешный TCP/UDP-тест подтверждением
постквантового режима.

## Откат и удаление

`ruter stop` останавливает только службы v2 и убирает только её
правила (`12200`, `12210`, таблица `220`). `ruter uninstall`
дополнительно удаляет её конфиг, подписку, бинарник и MetaCubeXD после
подтверждения. Установленные системные пакеты сохраняются. Если служба
временного шлюза всё ещё активна, установка и запуск v2 откажутся работать.

Проверки исходников: `PYTHONPATH=. python3 -m unittest discover -s tests -v`
и `bash -n bootstrap.sh ruter_v2/route.sh`. На Debian Test конфигурация дополнительно
проверялась командой `sing-box check` без запуска сети.

## Компоненты и лицензии

Ruter v2 не поставляет двоичные файлы в репозитории. Во время установки он
скачивает закреплённый архив `sing-box-lx 1.14.3-lx.20` и проверяет SHA-256,
а интерфейс MetaCubeXD получает из ветки `gh-pages` его официального проекта
с проверкой закреплённого commit SHA.
Лицензия sing-box-lx сохраняется рядом с установленным ядром; условия
MetaCubeXD опубликованы в его upstream-репозитории. Перед стабильным релизом
потребуется проверить совместимость с будущими версиями обоих проектов.
